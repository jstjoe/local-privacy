PII Detection Accuracy & Recall

How the OpenAI Privacy Filter and Microsoft Presidio — the leading open-source PII detectors — compare to Skyflow’s hosted detection API, benchmarked on the ai4privacy PII-Masking-300k dataset.

Overview

This overview summarizes how the two most widely used open-source PII detectors perform at finding personally identifiable information (PII) across multilingual text, and how they compare to Skyflow’s hosted detection API. All three were run over the same 1,000-example benchmark and scored the same way, so the numbers are directly comparable.

For most teams the metric that matters most is recall — the share of real PII the system actually catches. A missed identifier is a compliance and security risk, so the results below lead with recall alongside precision and overall F1.

How accuracy is measured

Results use three standard measures, computed at the span level so comparisons stay consistent across detectors:

Precision — of everything a detector flagged as PII, the share that was actually PII. Recall — of all the PII present, the share the detector correctly caught. F1 — the harmonic mean of the two, a single balanced score.

The headline table scores every detector out of the box: against all annotated PII, requiring an exact span match. A second view scores each detector only on the entity types it actually supports (“apples-to-apples”), which rewards narrow-but-accurate models.

The recall gap

Because recall is the metric most tied to risk, it is worth viewing on its own. Out of the box, the OpenAI Privacy Filter catches roughly two-thirds of the PII present, and Presidio closer to a third — while the hosted API stays near four-fifths.

Takeaways

The OpenAI Privacy Filter is the strongest open-source detector. It posts the highest open-source F1 (0.73 out of the box, 0.84 on its supported types) and the cleanest precision of any detector tested — the fewest false positives. The trade-off is speed: about 700 ms per request on CPU, so a GPU is recommended for production.
Recall is where the open-source options fall behind. The Privacy Filter catches ~68% of PII out of the box and Presidio ~37%, versus ~79% for the hosted API. Since a single missed identifier is the real exposure, this gap matters more than precision.
Presidio is fast but narrow. At ~14 ms per request it is by far the quickest, and it is near-perfect on structured types like email — but its English-only rules-plus-NER approach misses most other PII. Best as a cheap first pass or an email specialist, not a general detector.
Choose by constraint. For a fully self-hosted stack, the OpenAI Privacy Filter is the clear pick; where breadth of coverage and recall matter most — and hosting is acceptable — the managed API still leads, most visibly on recall.

Methodology

Dataset: ai4privacy PII-Masking-300k, a 1,000-example multilingual sample (German, English, Spanish, French, Italian, Dutch). Scoring: SemEval-2013 span-level evaluation via nervaluate. “Out of the box” scores every detector against all annotated PII with exact boundary-and-label matching; the apples-to-apples view scores each detector only on the entity types it claims to support.

Latency (single-request, p50): Presidio ~14 ms, Skyflow Detect ~107 ms, OpenAI Privacy Filter ~703 ms on CPU. Figures reflect overall results across the sample; per-language breakdowns are available. Detectors were run with default configurations and were not fine-tuned. Skyflow Detect is a hosted API included alongside the open-source detectors.
